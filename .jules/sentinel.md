## 2026-05-24 - [CRITICAL] Prevent Application Crash / DoS from ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH in Webhook Verification
**Vulnerability:** Found a Denial of Service (DoS) vulnerability in the backend's `verifyWebhookSignature` function located in `pandamarket/backend/src/utils/crypto.ts`. By sending a webhook with an invalid length signature, an attacker could force the Node.js `crypto.timingSafeEqual` to throw an unhandled `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH` exception, crashing the backend service.
**Learning:** `crypto.timingSafeEqual` requires the two buffers being compared to have the exact same byte length. If they do not, it throws an error instead of safely returning false. This is a common footgun when verifying external signatures if the payload signature length is not explicitly checked against the expected length before the comparison.
**Prevention:** Always compare buffer lengths explicitly (`if (signatureBuffer.length !== expectedBuffer.length) return false;`) before passing them to `crypto.timingSafeEqual` when verifying user-supplied or third-party webhooks and signatures.
