## 2025-01-20 - Webhook Signature DoS Vulnerability
**Vulnerability:** The `verifyWebhookSignature` function in `pandamarket/backend/src/utils/crypto.ts` was passing raw hex strings parsed into Buffers directly to `crypto.timingSafeEqual` without checking if their lengths matched. Node.js `crypto.timingSafeEqual` throws `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH` if buffer lengths differ. An attacker could craft a webhook request with an invalid signature length, crashing the backend service and causing a Denial of Service (DoS).
**Learning:** `crypto.timingSafeEqual` must only be called on buffers of equal length. Since HMAC signatures have fixed lengths based on the algorithm, differing lengths indicate tampering, but directly comparing them via timing-safe functions without length checking exposes the application to unhandled exceptions.
**Prevention:** Always compare `Buffer.length` before invoking `crypto.timingSafeEqual`. Return `false` gracefully if lengths do not match.
