## 2024-05-18 - Prevent DoS in Webhook Signature Verification
**Vulnerability:** The `verifyWebhookSignature` function in `pandamarket/backend/src/utils/crypto.ts` was passing a user-supplied signature directly to `crypto.timingSafeEqual()`. If the attacker provided a signature with a length different from the expected HMAC length, Node.js would throw an `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH` exception. Since this wasn't caught, it could crash the Node.js process, leading to a Denial of Service (DoS).
**Learning:** `crypto.timingSafeEqual()` requires both input buffers to be of identical length; otherwise, it throws instead of returning false. The length of an expected HMAC signature is public knowledge, so early-returning based on length mismatches is secure and prevents exceptions.
**Prevention:** Always ensure buffers have the same length before passing them to `crypto.timingSafeEqual()`, typically by doing a quick length check `if (a.length !== b.length) return false;` or by padding the buffers.
