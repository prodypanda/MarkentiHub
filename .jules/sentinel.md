## 2026-06-23 - Prevent DoS from ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH
**Vulnerability:** The `verifyWebhookSignature` function in `pandamarket/backend/src/utils/crypto.ts` compared `signature` and `expected` buffer lengths directly using `crypto.timingSafeEqual`. If the provided webhook signature length did not match the expected signature length, Node.js threw an unhandled `ERR_CRYPTO_TIMING_SAFE_EQUAL_LENGTH` exception, which could be abused by an attacker to crash the Node process and cause a Denial of Service (DoS).
**Learning:** `crypto.timingSafeEqual` strictly expects two buffers of the exact same length. If malicious input can control the length of the first buffer, the application will crash.
**Prevention:** Always check `bufferA.length === bufferB.length` and return `false` before calling `crypto.timingSafeEqual`, as the length check safely handles mismatched sizes and avoids the unhandled exception without introducing timing attacks (the expected length is constant).
