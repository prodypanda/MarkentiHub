## 2024-05-24 - Accessible Input Errors in Next.js\n**Learning:** When building accessible form components in Next.js, relying on string replacement (`label.replace(...)`) to generate IDs is fragile and prone to SSR hydration mismatches. Furthermore, custom input wrappers often forget to tie visual error and hint text back to the actual `<input>` field via `aria-describedby`.\n**Action:** Use React `useId()` for robust, hydration-safe ID generation. Always conditionally link the `input` to its helper spans using `aria-invalid` and `aria-describedby` so screen readers properly announce errors on focus.
