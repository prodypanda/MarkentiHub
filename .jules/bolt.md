## 2026-06-29 - Client-side Filtering Performance Optimization
**Learning:** In React components dealing with SWR or asynchronous data loading, setting inline default fallback arrays (like `data?.items || []`) breaks referential equality on every render. If this data is then filtered in unmemoized loops, it causes React to recalculate the filter array completely. Also, string operations like `.toLowerCase()` inside `.filter()` loops are very expensive (O(N) string allocations per render) and severely impact interaction speeds (like typing in a search bar).
**Action:** When filtering tables on the client side, wrap the operation in `useMemo`, define a stable `EMPTY_ARRAY` constant outside the component for loading fallbacks to prevent cache busting, and always hoist loop-invariant operations like `.toLowerCase()` outside the `.filter()` callback.
